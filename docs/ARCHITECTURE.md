## Основные модули

### Модель игры
- `Game`: владеет игроками, историей шагов и очередью отложенных input-эффектов.
- `Player`: хранит игрока, баланс и принадлежащие ему карты.
- `StepPhase`, `PendingStepPhase`, `FinishedStepPhase` описывают каждый шаг. Шаг считается законченным в тот момент, когда очередь эффектов, ожидающих ввод пользователя, закончена
- `DiceRollResult`: результат броска кубиков для игрока.
- `ClassMap`: мапа, позволяющая хранить произвольные типы безопасно(проще просто посмотреть, как оно используется)
- `InputEffectsQueue`: очередь, которая гарантирует управляемую и сериализованную обработку режима “ожидается ввод”.

### Карты, триггеры и эффекты
Это слой, где живут правила.

#### Карты (`Cards`)
- `Card` — базовый интерфейс для всех типов карт.
- Карта возвращает эффект через `getEffect(stepPhase, possessor)`.
- Конкретные типы карт (например, `NatureCard`, `BusinessCentreCard` и т.п.) задают конкретную логику эффектов.
- `CardCatalog` предоставляет поиск карты по id.

#### Триггеры (`Triggers`)
Триггеры решают, *должно ли* произойти событие.
- `Trigger` — предикат: `isTriggered(stepPhase, possessor)`.
- Композиция:
  - `AndTrigger` / `OrTrigger` объединяют триггеры.
  - Кубиковые триггеры (`AnyDiceTrigger`, `PlayerDiceTrigger`, `PossessorDiceTrigger`) матчят исходы броска.

#### Эффекты (`Effects`)
Эффекты — единственный компонент, который может менять состояние игры.
- `Effect.apply(stepPhase)` — применение эффекта
- `CompoundEffect` собирает несколько эффектов в один.
- `NoopEffect` очевидно.
- `MaybeEffect` применение эффекта, игнорирование исключений в эффекте.
- Конкретные эффекты:
  - `MoneyTransferEffect` (с `MoneyTransferType`)
  - `FineEffect`
  - `GrantCardEffect` / `RemoveCardEffect`

### Слой ввода игрока (`Effects`, `GameFacility`)
Некоторые карты/действия требуют дополнительного выбора игрока. 

#### Очередь инпут эффектов
- `AwaitInputEffect` кладёт `InputEffect<T>` в `Game.inputEffects`.
- Пока `Game.inputEffects` не пустая, текущий шаг нельзя завершить.
- `ProvideInputEffect` применяет `InputEffect<T>` только после:
  - проверки ввода без учёта контекста шага (`checkInput`)
  - проверки ввода с учётом шага (`isValid(stepPhase, input)`)
  - применения эффекта через `applyWithInput`.

## Поток выполнения

### Продвижение по шагам
В целом логика такая:
1. `GameDriver` создаёт новый `StepPhase`.
2. `StepPhase.runTriggerables()` перечисляет доступные triggerable через `Game.getTriggerables()` и оценивает их триггеры.
3. Сработавшие triggerable порождают эффекты (`Triggerable.getEffect`).
4. Эффекты применяются в контексте текущего шага.
5. Если нужен ввод, эффекты кладут input effects в очередь, и шаг остаётся незавершённым, пока очередь не будет обработана.
6. Когда ожидаемый ввод отсутствует, шаг переходит в finished фазу и может быть закрыт.

### Роль `GameDriver`
`GameDriver` — оркестратор:
- принимает команды
- обеспечивает корректность хода/фазы
- продвигает фазу (`WaitingDiceStepPhase -> FinishedActionStepPhase`)
- реализует `finishStep`, который может возвращать `null`, если `Game.inputEffects` не пустая
- создаёт ответы на эффекты, экспортируя простой интерфейс

## Расширение игры

При добавлении новых карт:
1. Опишите/реализуйте эффект(ы) карты в `cards`.
2. Если карте нужен выбор игрока, добавьте новый `InputEffect<T>`:
   - реализуйте `checkInput`, `isValid`, `applyWithInput`
   - обеспечьте путь через `AwaitInputEffect`/`ProvideInputEffect` в композиции эффектов карты
3. Если карта должна реагировать на условия (кубики/ход/фаза), задайте нужную композицию `Trigger` или добавьте новый тип триггера.

При добавлении новых форматов импорта/экспорта:
- следуйте шаблону `GameFacility`: `GameExporter`/`GameImporter` с JSON-реализациями.
